# V0.1 - 单Scene最小Demo

> **目标**: 验证 Tars 服务连通性，实现最基础的客户端-服务端通信
>
> **更新说明**: 
> - 鉴权改为模拟腾讯云接口，本地无真实账密
> - 单Scene设计，简化验证流程

## 完成时间
- 预计: 1 天
- 实际完成: 2026-04-30

## 功能特性

### 核心功能
1. **模拟鉴权** - 模拟腾讯云QQ登录鉴权流程（本地仅存储映射关系）
2. **客户端连接** - 客户端能连接 SceneServer
3. **简单移动** - 客户端发送移动请求，服务端处理
4. **位置广播** - 服务端将玩家位置广播给所有在线玩家
5. **内存存储** - 玩家位置暂存内存（不落库）

### 非功能性
- 支持 10-20 人同时在线测试
- 单 Scene (scene_id=1)

## 技术方案

### 鉴权设计（模拟腾讯云）

由于本地无真实QQ账密，采用 **OpenId 映射模式**：

```cpp
// 鉴权流程说明:
// 真实流程: 客户端 -> 腾讯云QQ登录 -> 获取 OpenId -> 业务服务器
// 本地流程: 客户端 -> 发送 OpenId -> 业务服务器验证并创建本地映射

// 登录请求 (简化版)
struct LoginReq {
    0 require string openId;        // 腾讯云下发的 OpenId
    1 optional string token;       // 可选的验证Token
};

// 登录响应
struct LoginRsp {
    0 require int ret;
    1 optional string msg;
    2 optional long sessionId;      // 业务侧Session
    3 optional string roleName;    // 如果已有角色
};

// 说明:
// - 客户端模拟生成 OpenId (如 "openid_123456")
// - 服务端验证 OpenId 格式有效性
// - 首次登录自动创建本地账号映射
// - 后续可扩展对接真实腾讯云鉴权接口
```

## 技术方案

### 服务架构 (极度简化)
```
Client <---> SceneServer (单实例)
              │
              └── 内存存储玩家位置
```

### .tars 接口设计

```tars
// Auth.tars - 鉴权协议
module GameDemo {

    // 登录请求 (模拟腾讯云)
    struct LoginReq {
        0 require string openId;        // 腾讯云 OpenId
        1 optional string token;        // 可选验证Token
    };
    
    struct LoginRsp {
        0 require int ret;
        1 optional string msg;
        2 optional long sessionId;      // 业务Session
    };
    
    interface AuthServant {
        // 模拟登录 (验证OpenId格式)
        int login(1 require LoginReq req, 2 require LoginRsp rsp);
        
        // 心跳保活
        int heartBeat(1 require long sessionId);
    };
};

// Scene.tars - 场景协议
module GameDemo {

    // 玩家信息
    struct PlayerInfo {
        0 require long playerId;       // 由sessionId映射
        1 require string openId;       // 原始openId
        2 require float x;
        3 require float y;
        4 require float z;
    };
    
    // 进入场景请求
    struct EnterSceneReq {
        0 require long sessionId;
    };
    
    struct EnterSceneRsp {
        0 require int ret;
        1 optional string msg;
        2 optional PlayerInfo self;              // 自己的信息
        3 optional vector<PlayerInfo> players;   // 场景内其他玩家
    };
    
    // 移动请求
    struct MoveReq {
        0 require long sessionId;
        1 require float x;
        2 require float y;
        3 require float z;
    };
    
    struct MoveRsp {
        0 require int ret;
        1 optional string msg;
    };
    
    // 离开场景
    struct LeaveSceneReq {
        0 require long sessionId;
    };
    
    // 客户端回调接口
    interface SceneClient {
        int onPlayerEnter(1 require PlayerInfo player);
        int onPlayerMove(1 require PlayerInfo player);
        int onPlayerLeave(1 require long playerId);
        int onError(1 require int code, 2 require string msg);
    };
    
    interface SceneServant {
        // 进入场景
        int enterScene(1 require EnterSceneReq req, 2 require EnterSceneRsp rsp);
        
        // 移动
        int move(1 require MoveReq req, 2 require MoveRsp rsp);
        
        // 离开场景
        int leaveScene(1 require LeaveSceneReq req);
    };
};
```

## 实现步骤

### Step 1: 创建协议文件
```
tars/Auth.tars    # 鉴权协议
tars/Scene.tars   # 场景协议
```

### Step 2: 创建 AuthServer (极简版)
```bash
cd /workspace/server
mkdir -p AuthServer
/usr/local/tars/cpp/script/cmake_tars_server.sh AuthServer AuthServer Auth
```
> 初期可与 SceneServer 合并，先用 AuthServer 验证鉴权流程

### Step 3: 创建 SceneServer
```bash
cd /workspace/server
/usr/local/tars/cpp/script/cmake_tars_server.sh SceneServer SceneServer Scene
```

### Step 4: 实现 AuthServer 业务逻辑
- AuthImp::login() - 验证 OpenId 格式，生成 Session
- Session 管理 (内存 Map)
- 心跳保活

### Step 5: 实现 SceneServer 业务逻辑
- SceneImp::enterScene() - 处理玩家进入，广播给其他人
- SceneImp::move() - 处理移动请求，广播位置变化
- SceneImp::leaveScene() - 处理玩家离开，通知其他人
- 定时广播所有玩家位置

### Step 6: 创建客户端
- C++ 客户端连接 AuthServer 进行登录
- 获取 Session 后连接 SceneServer
- 实现 SceneClient Prx 回调
- 命令行交互

### Step 7: 测试
- 启动 AuthServer
- 启动 SceneServer
- 启动多个客户端
- 验证登录和移动同步

## 架构图 (V0.1 简化版)

```
┌──────────────────────────────────────────────────────────────┐
│                         Client                               │
│                   (C++ 命令行客户端)                          │
└──────┬───────────────────────────────────────────────────────┘
       │
       │ 1. login(openId) ──► GameDemoScene (合并鉴权+场景)
       │    ◄── sessionId, playerId
       │
       │ 2. enterScene(sessionId) ──► GameDemoScene
       │    ◄── playerId, players[]
       │
       │ 3. move(x,y,z) ──► GameDemoScene
       │    ◄── 响应
       │
       │ 4. logout ──► GameDemoScene
       ▼
┌──────────────────────────────────────────────────────────────┐
│                   GameDemoScene                              │
│              (App: GameDemo, Server: GameDemoScene)          │
│              Servant: GD (interface GameServant)             │
│              内存存储: map<sessionId, openId>                │
│                       map<playerId, PlayerInfo>             │
└──────────────────────────────────────────────────────────────┘
```

> **特别说明**: V0.1 将鉴权和场景**合并**为一个服务，这是**有意为之**的简化：
> - 目的：快速验证 Tars 服务连通性和基础通信
> - 优点：部署简单，测试方便
> - **重要**: 从 V0.2 开始，将拆分为 LobbyServer（统一接入层）+ SceneServer（场景）
>   - Client **只连接 LobbyServer**
>   - 场景切换对客户端透明，无需重连
