## LoadBot 架构

```
main (单进程)
    │
    ├── LoadBot × N  ──(TARS RPC)──▶ LobbyServer ──▶ SceneServer ──▶ DBServer
    │     │                              ▲
    │     └── BotPushCallback ◀── Lobby2ClientPush ─┘
    │
    └── MetricsCollector (单例，所有 Bot 共享)
```

> **关键**: 单进程管理所有 Bot，Bot 只与 LobbyServer 交互。MetricsCollector 全局采集，运行结束时一次性保存 JSON。

## 接口设计

### Bot 状态机

```
CONNECTING ──▶ LOGGING_IN ──▶ REGISTERING_PUSH ──▶ IDLE ──▶ MOVING
                                                                      │
                    FAILED ◀─────────────────────────────────────────┘
                                                                      │
                    LOGGING_OUT ◀─────────────────────────────────────┘
```

| 状态 | 说明 |
|------|------|
| CONNECTING | 初始化 TARS 通信器 |
| LOGGING_IN | 同步登录获取 playerId + sessionKey |
| REGISTERING_PUSH | 注册推送回调 + 设置 PushCallback |
| IDLE | 空闲（压测中不使用） |
| MOVING | 正常移动中 |
| LOGGING_OUT | 登出中 |
| FAILED | 初始化失败 |

### LoadBot 类

```cpp
class LoadBot {
public:
    LoadBot(int botIndex, int sceneId = 1);

    // 完整初始化链路: login → registerPush → setCallback → heartbeat → enterScene → scatterMove
    bool initialize(CommunicatorPtr comm, LobbyServantPrx lobbyPrx);

    // 随机移动 (异步，并发窗口控制)
    void randomMove();

    // 异步回调
    void onMoveResponse(Int32 ret, const MoveRsp& rsp, time_point sendTime);
    void onMoveException();

    // 登出
    void logout();
    void joinHeartbeat();

    BotState getState() const;

private:
    // 心跳 (独立线程，每 3 秒)
    void startHeartbeat(int intervalSeconds);

    // 并发控制
    static constexpr int MAX_INFLIGHT = 3;   // 每个 Bot 最多 3 个并发 move
    atomic<int> _moveInflight{0};
};
```

### BotMoveCallback (异步移动回调)

```cpp
class BotMoveCallback : public LobbyServantPrxCallback {
public:
    BotMoveCallback(time_point sendTime, LoadBot* bot);

    virtual void callback_move(Int32 ret, const MoveRsp& rsp) override;
    virtual void callback_move_exception(Int32 ret) override;
};
```

> **并发窗口**: `randomMove()` 发送前检查 `_moveInflight < MAX_INFLIGHT`，发送时 `_moveInflight++`，回调中 `--`。异常回调也必须递减，否则窗口死锁。

### BotPushCallback (广播接收)

```cpp
class BotPushCallback : public Lobby2ClientPushPrxCallback {
    callback_onPlayerEnter    → MetricsCollector::recordPushNotify(ENTER)
    callback_onPlayerMove     → MetricsCollector::recordPushNotify(MOVE)
    callback_onPlayerLeave    → MetricsCollector::recordPushNotify(LEAVE)
    callback_onPlayerOffline  → MetricsCollector::recordPushNotify(OFFLINE)
    callback_onPlayerOnline   → MetricsCollector::recordPushNotify(ONLINE)
};
```

### MetricsCollector (指标采集，单例)

```cpp
class MetricsCollector {
public:
    static MetricsCollector& instance();

    void recordMoveLatency(int64_t latencyMs);
    void recordPushNotify(PushType type);
    void recordLoginResult(bool success, int64_t latencyMs);
    void setOnlineBots(int count);
    void setParams(int botCount, int moveFreqSec, int sceneId, int durationSec);
    void initRunDir();    // 初始化输出路径
    void finalSave();     // 运行结束时一次性保存
};
```

## 调用链路

### Bot 初始化

```
login(username, password)              → 获取 playerId + sessionKey
  └─ registerPush(playerId)            → 注册推送
  └─ tars_set_push_callback(Callback)  → 设置 Push 回调
  └─ startHeartbeat(3)                 → 心跳保活
  └─ enterScene(playerId, key, sceneId)→ 进入场景
  └─ scatterMove()                     → 首次随机分散
```

> 压测账号通过 SQL 预创建，Bot 登录时 `hasCharacter=true`，无需注册和创角。

### 移动广播

```
Bot A ──async_move──▶ LobbyServer ──move──▶ SceneServer ──AOI──▶ Scene2LobbyPush
                          ▲                                         │
                          └── onPlayerMove ◀── Lobby2ClientPush ◀──┘
                                  │
                          Bot B/C/D... 收到广播
```

### 移动策略

| 阶段 | 行为 | 说明 |
|------|------|------|
| 初始分散 | 跳到 [0~999, 0~999, 0] 随机位置 | 避免扎堆导致广播风暴 |
| 正常移动 | 步长 ±5，保持分散 | 维持空间分布 |

## 压测结果

> 场景配置: 1000×1000 地图，九宫格 gridSize=50，AOI 视距 150×150
> 每组测试时长 60 秒，客户端并发窗口 MAX_INFLIGHT=3

### 500 Bot

| 频率 | 总移动回调次数 | avg(ms) | p50(ms) | p99(ms) | max(ms) | moveNotify | avgPerBotPerSec |
|------|-----------|---------|---------|---------|---------|------------|-----------------|
| 1次/s | 30,000 | 14 | 15 | 29 | 33 | 299,613 | 9.99 |
| 3次/s | 90,000 | 15 | 16 | 31 | 36 | 930,312 | 31.01 |
| 5次/s | 149,500 | 16 | 16 | 32 | 38 | 1,551,393 | 51.71 |
| 10次/s | 297,000 | 15 | 15 | 30 | 39 | 3,048,152 | 101.61 |
| 20次/s | 589,000 | 14 | 15 | 30 | 44 | 6,161,261 | 205.38 |
| 30次/s | 705,350 | 33 | 25 | 121 | 3,912 | 5,931,740 | 197.72 |

> 20次/s 以内延迟平稳（p99≤30ms），30次/s 出现明显过载。安全上限约 20次/s。

### 1000 Bot

| 频率 | 总移动回调次数 | avg(ms) | p50(ms) | p99(ms) | max(ms) | moveNotify | avgPerBotPerSec |
|------|-----------|---------|---------|---------|---------|------------|-----------------|
| 1次/s | 60,000 | 34 | 33 | 80 | 99 | 1,251,235 | 20.85 |
| 3次/s | 180,000 | 34 | 34 | 81 | 98 | 3,777,472 | 62.96 |
| 5次/s | 298,000 | 34 | 33 | 81 | 101 | 6,147,488 | 102.46 |
| 10次/s | 567,303 | 135 | 115 | 416 | 552 | 11,657,450 | 194.29 |

> 5次/s 以内延迟稳定（p99≈81ms），10次/s 过载。瓶颈在广播推送量而非请求频率。

### 关键发现

1. **广播推送是主要瓶颈**: 1000 Bot 3次/s 和 5次/s 的 p99 几乎相同（81ms），延迟由广播量决定
2. **线性扩展区间**: 500×20 和 1000×5 的总 QPS 接近，延迟都在可接受范围
3. **非线性恶化**: 超过服务端处理能力后延迟急剧上升，无渐变过渡区
