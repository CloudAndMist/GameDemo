# GameDemo RPG 游戏 Demo - 项目设计总览

## 1. 项目概述

一个基于 Tars 框架的简易 RPG 游戏 Demo，用于验证分布式服务架构和性能指标。

## 2. 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| **后端框架** | Tars C++ | 分布式 RPC 框架 |
| **数据库** | MySQL 8.0 + TcaplusDB 3.67 | 持久化存储 |
| **客户端** | C++ 自研 | 命令行/简易 SDL2 UI |
| **部署** | Docker 自建 | 私有化部署 |
| **压测** | Python/C++ Bot | 模拟客户端 |

## 3. 服务架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                Client                                   │
│                     【单一接入点：只连接 LobbyServer】                    │
│                        Tars 协议 (TCP)                                   │
└────────────────────────────────┬────────────────────────────────────────┘
                                 │
                                 │ 所有请求都通过 LobbyServer 转发
                                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          LobbyServer                                    │
│                (10001 主servant, 10003 Push servant)                     │
│                    【统一接入层 / 网关层】                                │
│                                                                          │
│  - 客户端连接管理（心跳/断连/重连）                                        │
│  - playerId ↔ connId 映射管理                                            │
│  - 腾讯云 OpenId 鉴权 (模拟)                                             │
│  - 角色列表/创建/选择 (大厅功能)                                          │
│  - 请求路由与转发                                                         │
│  - 安全过滤（防止恶意数据包直接攻击内部服务）                               │
└───────────┬─────────────────────────────────────────────────────────────┘
            │
            │ Tars RPC (内部调用，Client 不可见)
            │
            ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      【内部服务 - Client 不可见】                         │
│                                                                            │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────────────┐  │
│  │    DBServer     │  │  SceneServer   │  │   其他服务 (V0.4+)       │  │
│  │    (10000)      │  │   (10002)      │   │   BattleServer 等       │  │
│  │                 │  │                │  │                         │  │
│  │ - MySQL 账号/角色│  │ - 场景管理     │  │ - 战斗/匹配/社交        │  │
│  │ - Tcaplus 位置  │  │ - 移动处理     │  │ - 按需扩展              │  │
│  │ - 数据持久化     │  │ - 位置广播     │  │                         │  │
│  └─────────────────┘  │ - AOI (V0.4+) │  └─────────────────────────┘  │
│                       └─────────────────┘                               │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                              通信流程                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  同步 RPC 调用 (请求-响应):                                                │
│  ─────────────────────────                                               │
│  Client ──▶ LobbyServer ──▶ DBServer       (登录/账号/角色数据)          │
│  Client ──▶ LobbyServer ──▶ SceneServer    (进入场景/移动请求)            │
│                                                                          │
│  异步回调 (直接 RPC 调用):                                                 │
│  ─────────────────────                                                  │
│  SceneServer ──▶ LobbyServer ──▶ Client   (推送：其他玩家移动等)           │
│     ↑ 直接调用 LobbyPush 接口，无需注册                                   │
│                                                                          │
│  注意:                                                                   │
│  - DBServer 无需回调，同步 RPC 即可                                        │
│  - SceneServer 直接通过服务名调用 LobbyServer                             │
│  - 内部服务间也可直接 RPC，不都经过 LobbyServer                            │
└─────────────────────────────────────────────────────────────────────────┘
```

> **架构说明**:
> - **单一接入点**: Client 只连接 LobbyServer，不直接连接 SceneServer 或 DBServer
> - **统一网关**: LobbyServer 充当网关，负责连接管理、路由转发、安全过滤
> - **内部通信**: 内部服务通过 TARS RPC 互相调用，Client 无感知
> - **场景切换透明**: 玩家切换场景时，无需断开与 LobbyServer 的连接
> - **推送机制**: SceneServer 直接调用 LobbyServer 的 `LobbyPush` 接口，无需注册

## 4. 服务职责

### 4.1 LobbyServer (V0.2+)

- **端口**: 20001
- **职责**:
  - 客户端连接接入（**统一接入层**）
  - **腾讯云 OpenId 鉴权** (模拟)
  - playerId 管理与 connId 映射
  - 角色列表/创建/选择 (大厅功能)
  - 场景切换入口
  - 请求路由与转发
  - 实现 `LobbyPush` 接口，接收 SceneServer 的回调
- **鉴权说明**: 
  - 真实场景: 客户端 → 腾讯云QQ登录 → 获取 OpenId → 业务服务器
  - 本地Demo: 客户端 → 发送 OpenId → LobbyServer 验证并创建本地映射

### 4.2 SceneServer

- **端口**: 20002+ (多实例)
- **职责**:
  - 地图场景管理
  - 玩家进出场景
  - 玩家移动处理
  - AOI 九宫格视野管理
  - 位置广播同步
  - **直接调用** `LobbyServer.LobbyPushObj` 推送玩家事件
- **不管理**: 心跳由 LobbyServer 统一管理，SceneServer 不关心
- **注意**: Client 不可直接连接，通过 LobbyServer 转发

### 4.3 DBServer

- **端口**: 10000
- **职责**:
  - MySQL 操作：账号、角色基础信息
  - TcaplusDB 操作：玩家位置、在线状态
  - 数据落地一致性
- **注意**: Client 不可见，仅供内部服务调用

## 5. 数据存储设计

### 5.1 MySQL 表设计

```sql
-- 账号表
CREATE TABLE `accounts` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `qq_number` VARCHAR(20) UNIQUE NOT NULL COMMENT 'QQ号',
    `password` VARCHAR(128) NOT NULL COMMENT '密码(加密)',
    `create_time` BIGINT COMMENT '创建时间(毫秒时间戳)',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_qq_number (`qq_number`)
);

-- 角色表
CREATE TABLE `roles` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `account_id` BIGINT NOT NULL COMMENT '所属账号ID',
    `role_name` VARCHAR(64) NOT NULL COMMENT '角色名',
    `job` INT DEFAULT 0 COMMENT '职业',
    `level` INT DEFAULT 1 COMMENT '等级',
    `exp` BIGINT DEFAULT 0 COMMENT '经验',
    `hp` INT DEFAULT 100 COMMENT '生命值',
    `mp` INT DEFAULT 50 COMMENT '魔法值',
    `x` FLOAT DEFAULT 0 COMMENT 'X坐标',
    `y` FLOAT DEFAULT 0 COMMENT 'Y坐标',
    `z` FLOAT DEFAULT 0 COMMENT 'Z坐标',
    `scene_id` INT DEFAULT 1 COMMENT '所在场景ID',
    `create_time` BIGINT COMMENT '创建时间(毫秒时间戳)',
    `last_login_time` BIGINT COMMENT '最后登录时间(毫秒时间戳)',
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_account_id (`account_id`)
);

-- 玩家在线状态表（心跳由 LobbyServer 管理，此表用于持久化）
CREATE TABLE `player_online` (
    `player_id` BIGINT PRIMARY KEY COMMENT '玩家ID',
    `scene_id` INT DEFAULT 0 COMMENT '所在场景ID',
    `lobby_server` VARCHAR(64) DEFAULT '' COMMENT '连接的LobbyServer',
    `login_time` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '登录时间',
    `last_heartbeat` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后心跳时间(LobbyServer管理)',
    INDEX idx_scene_id (`scene_id`)
);
```

## 7. 开发工作流

### 7.1 本地开发环境

```bash
# 1. 启动基础 Tars 服务 (Docker)
docker-compose -f scripts/docker-compose.yml up -d

# 2. 进入编译容器
docker exec -it tars-cpp-compiler bash

# 3. 编译单个服务
cd /workspace/server/LobbyServer/build
cmake .. -DTARS_WEB_HOST=http://tars-framework:3000 -DTARS_TOKEN=${TOKEN}
make -j4

# 4. 打包发布
make LobbyServer-tar
make LobbyServer-upload
```

### 7.2 服务测试流程

每个服务开发完成后，通过 Tars Web 界面发布，然后使用客户端或 Bot 进行联调测试。

## 10. 接口一览

### 10.1 Client → LobbyServer

| 接口 | 方法 | 说明 |
|------|------|------|
| `LobbyServant` | `login` | 登录 |
| `LobbyServant` | `registerAccount` | 注册账号 |
| `LobbyServant` | `createRole` | 创建角色 |
| `LobbyServant` | `getRoleList` | 获取角色列表 |
| `LobbyServant` | `selectRole` | 选择角色进入游戏 |
| `LobbyServant` | `heartbeat` | 心跳 |
| `LobbyServant` | `enterScene` | 进入场景 |
| `LobbyServant` | `move` | 移动 |

### 10.2 LobbyServer → Client (回调，通过 PushCallback 机制)

| 接口 | 方法 | 说明 |
|------|------|------|
| `Lobby2ClientPush` | `onPlayerEnter` | 推送新玩家进入 |
| `Lobby2ClientPush` | `onPlayerMove` | 推送玩家移动 |
| `Lobby2ClientPush` | `onPlayerLeave` | 推送玩家离开 |

### 10.3 SceneServer → LobbyServer (异步回调)

| 接口 | 方法 | 说明 |
|------|------|------|
| `Scene2LobbyPush` | `onPlayerEnter` | 通知玩家进入场景 |
| `Scene2LobbyPush` | `onPlayerMove` | 通知玩家移动 |
| `Scene2LobbyPush` | `onPlayerLeave` | 通知玩家离开场景 |
