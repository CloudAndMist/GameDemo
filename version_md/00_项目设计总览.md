# GameDemo RPG 游戏 Demo - 项目设计总览

## 1. 项目概述

一个基于 Tars 框架的简易 RPG 游戏 Demo，用于验证分布式服务架构和性能指标。

## 2. 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| **后端框架** | Tars C++ | 分布式 RPC 框架 |
| **数据库** | MySQL 8.0 + TcaplusDB 3.67 | 持久化存储 |
| **客户端** | C++ 自研 | 命令行/简易 SDL2 UI |
| **部署** | Docker 自建 | 私有化部署 |
| **压测** | Python/C++ Bot | 模拟客户端 |

## 3. 服务架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                Client                                   │
│                     【单一接入点：只连接 LobbyServer】                    │
│                        Tars 协议 (TCP)                                   │
└────────────────────────────────┬────────────────────────────────────────┘
                                 │
                                 │ 所有请求都通过 LobbyServer 转发
                                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          LobbyServer                                    │
│                             (10000)                                     │
│                    【统一接入层 / 网关层】                                │
│                                                                          │
│  - 客户端连接管理（心跳/断连/重连）                                        │
│  - playerId ↔ connId 映射管理                                            │
│  - 腾讯云 OpenId 鉴权 (模拟)                                             │
│  - 角色列表/创建/选择 (大厅功能)                                          │
│  - 请求路由与转发                                                         │
│  - 安全过滤（防止恶意数据包直接攻击内部服务）                               │
└───────────┬─────────────────────────────────────────────────────────────┘
            │
            │ Tars RPC (内部调用，Client 不可见)
            │
            ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      【内部服务 - Client 不可见】                         │
│                                                                            │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────────────┐  │
│  │    DBServer     │  │  SceneServer   │  │   其他服务 (V0.4+)       │  │
│  │    (10000)      │  │   (10002+)     │  │   BattleServer 等       │  │
│  │                 │  │                │  │                         │  │
│  │ - MySQL 账号/角色│  │ - 场景管理     │  │ - 战斗/匹配/社交        │  │
│  │ - Tcaplus 位置  │  │ - 移动处理     │  │ - 按需扩展              │  │
│  │ - 数据持久化     │  │ - 位置广播     │  │                         │  │
│  └─────────────────┘  │ - AOI (V0.4+) │  └─────────────────────────┘  │
│                       └─────────────────┘                               │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                              通信流程                                    │
├─────────────────────────────────────────────────────────────────────────┤
│  Client ──▶ LobbyServer ──▶ DBServer       (登录/账号/角色数据)          │
│  Client ──▶ LobbyServer ──▶ SceneServer  (进入场景/移动请求)            │
│                                                                          │
│  SceneServer ──▶ LobbyServer ──▶ Client   (回调推送：其他玩家移动等)      │
│                                                                          │
│  注意: 内部服务之间也可直接通过 Tars RPC 通信，                          │
│        不必都经过 LobbyServer (如 SceneServer 直接调用 DBServer)          │
└─────────────────────────────────────────────────────────────────────────┘
```

> **架构说明**:
> - **单一接入点**: Client 只连接 LobbyServer，不直接连接 SceneServer 或 DBServer
> - **统一网关**: LobbyServer 充当网关，负责连接管理、路由转发、安全过滤
> - **内部通信**: 内部服务通过 Tars RPC 互相调用，Client 无感知
> - **场景切换透明**: 玩家切换场景时，无需断开与 LobbyServer 的连接

## 4. 服务职责

### 4.1 LobbyServer (V0.1+)
- **端口**: 20001
- **职责**:
  - 客户端连接接入（**统一接入层**）
  - **腾讯云 OpenId 鉴权** (模拟)
  - playerId 管理与 connId 映射
  - 角色列表/创建/选择 (大厅功能)
  - 场景切换入口
  - 请求路由与转发
- **鉴权说明**: 
  - 真实场景: 客户端 → 腾讯云QQ登录 → 获取 OpenId → 业务服务器
  - 本地Demo: 客户端 → 发送 OpenId → LobbyServer 验证并创建本地映射

### 4.2 SceneServer
- **端口**: 20002+ (多实例)
- **职责**:
  - 地图场景管理
  - 玩家移动处理
  - 位置广播同步
  - 可扩展 AOI 九宫格
- **注意**: Client 不可直接连接，通过 LobbyServer 转发

### 4.3 DBServer
- **端口**: 10000
- **职责**:
  - MySQL 操作：账号、角色基础信息
  - TcaplusDB 操作：玩家位置、在线状态
  - 数据落地一致性
- **注意**: Client 不可见，仅供内部服务调用

## 5. 数据存储设计

### 5.1 MySQL 表设计

```sql
-- 账号表
CREATE TABLE `t_account` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `qq_number` VARCHAR(20) UNIQUE NOT NULL COMMENT 'QQ号',
    `password` VARCHAR(128) NOT NULL COMMENT '密码(加密)',
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 角色表
CREATE TABLE `t_role` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `account_id` BIGINT NOT NULL,
    `role_name` VARCHAR(64) NOT NULL,
    `level` INT DEFAULT 1,
    `scene_id` INT DEFAULT 1,
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (`account_id`) REFERENCES `t_account`(`id`)
);
```

### 5.2 TcaplusDB 表设计

```protobuf
// PlayerPos 表
table PlayerPos {
    player_id: int64;
    scene_id: int32;
    x: float;
    y: float;
    z: float;
    last_move_time: int64;
    
    primary_key(player_id);
}
```

> **目录设计说明**：

> - 每个服务独立编译，互不影响

## 7. 开发工作流

### 7.1 本地开发环境

```bash
# 1. 启动基础 Tars 服务 (Docker)
docker-compose -f scripts/docker-compose.yml up -d

# 2. 进入编译容器
docker exec -it tars-cpp-compiler bash

# 3. 编译单个服务
cd /workspace/server/LobbyServer/build
cmake .. -DTARS_WEB_HOST=http://tars-framework:3000 -DTARS_TOKEN=${TOKEN}
make -j4

# 4. 打包发布
make LobbyServer-tar
make LobbyServer-upload
```

### 7.2 服务测试流程

每个服务开发完成后，通过 Tars Web 界面发布，然后使用客户端或 Bot 进行联调测试。
