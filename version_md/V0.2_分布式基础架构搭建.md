# V0.2 - 分布式基础架构搭建

> **目标**: 搭建完整的分布式游戏后端架构，实现 DBServer、LobbyServer、SceneServer 三层服务
>
> **完成时间**: 2026-05-02

## 架构概述

V0.2 是整个项目的核心基础设施版本，建立完整的三层服务架构：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           客户端 (Client)                               │
└────────────────────────────────┬────────────────────────────────────────┘
                                 │ TARS RPC
                                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        LobbyServer (接入层/网关)                         │
│  • 账号/角色管理                                                          │
│  • 客户端连接管理                                                          │
│  • 请求路由转发                                                            │
│  • 推送转发 (PushCallback)                                               │
└────────────────┬────────────────────────────────────────────────────────┘
                 │ RPC
        ┌────────┴────────┐
        ▼                 ▼
┌───────────────┐  ┌─────────────────┐
│  DBServer     │  │  SceneServer    │
│  (数据层)      │  │  (逻辑层)        │
│               │  │                 │
│  • 账号持久化  │  │  • 场景管理      │
│  • 角色CRUD   │  │  • 玩家同步      │
│  • 数据存储    │  │  • 移动广播      │
└───────────────┘  └─────────────────┘
```

## 服务通信矩阵

| 调用方 | 被调用方 | 接口 | 模式 | 说明 |
|--------|---------|------|------|------|
| Client | LobbyServer | `LobbyServant` | 同步 RPC | 登录/创建角色等 |
| Client | LobbyServer | `Lobby2ClientPush` | PushCallback | 接收推送 |
| LobbyServer | DBServer | `DBServant` | 同步 RPC | 数据持久化 |
| LobbyServer | SceneServer | `SceneServant` | 同步 RPC | 转发场景请求 |
| SceneServer | LobbyServer | `Scene2LobbyPush` | 异步 RPC | 推送玩家事件 |

## 推送机制 (TARS PushCallback)

### 设计原则

使用 TARS 内置的 PushCallback 机制实现服务端向客户端推送：

| 对比项 | 传统方案 | TARS PushCallback |
|--------|----------|-------------------|
| 调用方式 | 客户端暴露端口被调用 | 客户端注册回调，服务端推送 |
| 复杂度 | 需要维护回调注册/注销 | TARS 框架自动管理 |
| 适用场景 | 有公网IP的服务端 | 客户端/内网环境 |
| 依赖关系 | 端口映射/NAT穿透 | 无需端口暴露 |

### 推送流程

```
┌─────────┐                    ┌─────────────┐                      ┌─────────────┐
│ Client  │                    │ LobbyServer │                      │ SceneServer │
└────┬────┘                    └──────┬──────┘                      └──────┬──────┘
     │                                │                                    │
     │   1. enterSceneReq             │                                    │
     │───────────────────────────────▶│                                    │
     │                                │                                    │
     │                                │     2. enterSceneReq  (sync)       │
     │                                │───────────────────────────────────▶│
     │                                │                                    │
     │                                │                      3. 处理进入    │
     │                                │◀───────────────────────────────────│
     │                                │                      4. 异步回调   │
     │      5. enterSceneResp         │◀───────────────────────────────────│
     │◀───────────────────────────────│                                    │
     │                                │                                    │
     │                                │     6. onPlayerEnter (async)       │
     │◀───────────────────────────────│                                    │
     │                                │                                    │
     │   7. PushCallback 推送其他玩家   │                                    │
     ▼                                ▼                                    ▼
```

**核心流程**：
1. 客户端连接 LobbyServer 时，调用 `tars_set_push_callback()` 注册回调
2. LobbyServer 保存客户端的 `CurrentPtr`（代表连接）
3. 收到 SceneServer 的回调时，通过 `CurrentPtr` 推送消息给客户端

## Tars 接口定义

### DBServer 接口

```tars
interface DBServant
{
    // Account operations
    int createAccount(string qqNumber, string password, out long accountId);
    int getAccountByQQ(string qqNumber, out AccountInfo account);
    int accountExists(string qqNumber, out bool exists);

    // Role operations
    int createRole(long accountId, string roleName, int job, out RoleInfo role);

    int updateRole(RoleInfo role);

```

### LobbyServer 接口

```tars
interface LobbyServant
{
    // 登录
    int login(LoginReq req, out LoginRsp rsp);

    // 注册账号
    int registerAccount(RegisterReq req, out RegisterRsp rsp);

    // 创建角色
    int createRole(CreateRoleReq req, out CreateRoleRsp rsp);

    // 获取角色列表
    int getRoleList(GetRoleListReq req, out GetRoleListRsp rsp);

    // 移动 (转发给 SceneServer)

};
```

### SceneServer 接口

```tars
interface SceneServant
{
    // 进入场景
    int enterScene(EnterSceneReq req, out EnterSceneRsp rsp);

    // 移动
    int move(MoveReq req, out MoveRsp rsp);

    // 心跳

    // 获取场景玩家列表

    // 离开场景

```

### 推送接口

```tars
// SceneServer → LobbyServer 推送接口
interface Scene2LobbyPush
{
    // 玩家进入场景通知 (notifyList: 需要通知的其他玩家ID列表)
    int onPlayerEnter(vector<long> notifyList, long playerId, int sceneId, PlayerInfo player);

    // 玩家移动通知
    int onPlayerMove(vector<long> notifyList, long playerId, int sceneId, float x, float y, float z);

    // 玩家离开场景通知
    int onPlayerLeave(vector<long> notifyList, long playerId, int sceneId);
};

// LobbyServer → Client 推送接口 (客户端实现)
interface Lobby2ClientPush
{
    int onPlayerEnter(PlayerEnterNotify notify);
    int onPlayerMove(PlayerMoveNotify notify);
    int onPlayerLeave(PlayerLeaveNotify notify);
};
```

## 踩坑记录

### TARS Response 复用问题 (已解决)

**问题描述**：
`getScenePlayers` 返回的玩家列表出现重复，playerId 多次出现。

**根因**：
TARS 框架的 Response 对象可能被复用，旧数据残留在 buffer 中。

**修复方案**：
```cpp
tars::Int32 SceneImp::getScenePlayers(...)
{
    rsp.ret = 0;
    rsp.msg = "success";
    rsp.players.clear();  // 必须清空，释放残留数据
    // ...
}
```

**教训**：
- TARS 的输出参数是 **状态ful** 的，需要开发者主动管理生命周期
- 每次返回前，显式清空容器，避免残留数据累积
