## 概述

V0.2 是整个项目的核心基础设施版本，主要目标：
1. 完善 **DBServer** - 账号/角色数据持久化

## 2. 推送机制设计 (TARS PushCallback)

### 2.1 设计原则

**核心机制**: 使用 TARS 内置的 PushCallback 机制实现服务端向客户端推送

| 对比项 | 传统方案 | TARS PushCallback |
|--------|----------|-------------------|
| 调用方式 | 客户端暴露端口被调用 | 客户端注册回调，服务端推送 |
| 复杂度 | 需要维护回调注册/注销 | TARS 框架自动管理 |
| 适用场景 | 有公网IP的服务端 | 客户端/内网环境 |
| 依赖关系 | 端口映射/NAT穿透 | 无需端口暴露 |

**TARS PushCallback 流程**:
1. 客户端连接 LobbyServer 时，调用 `tars_set_push_callback()` 注册回调
2. LobbyServer 保存客户端的 `CurrentPtr`（代表连接）
3. 收到 SceneServer 的 LobbyPush 回调时，通过 `CurrentPtr` 推送消息给客户端

### 2.2 调用流程

```
┌─────────┐                    ┌─────────────┐                      ┌─────────────┐
│ Client  │                    │ LobbyServer │                      │ SceneServer │
└────┬────┘                    └──────┬──────┘                      └──────┬──────┘
     │                                │                                    │
     │   1. enterSceneReq             │                                    │
     │───────────────────────────────▶│                                    │
     │                                │                                    │
     │                                │     2. enterSceneReq  (sync)       │
     │                                │───────────────────────────────────▶│
     │                                │                                    │ 3. 处理进入
     │                                │    					               │◀───────────
     |								  |									   | 4. 异步回调,同步给场景中的其他玩家
     │                                │         5. enterSceneResp          │◀───────────
     │                                │◀───────────────────────────────────│
     │      6. enterSceneResp         │                                     │
     │◀───────────────────────────── ─│			                           |
     │                                │                                     │ 
     │                                │      7. onPlayerEnter (async)       │
     │                                │◀───────────────────────────────────│
     │                                │                                    │
     │                                │                                    │
```

## 3. 服务通信矩阵

| 调用方 | 被调用方 | 接口 | 模式 | 说明 |
|--------|---------|------|------|------|
| Client | LobbyServer | `LobbyServant` | 同步 RPC | 登录/创建角色等 |
| Client | LobbyServer | `SceneCallback` | PushCallback | 接收推送 (客户端实现回调) |
| LobbyServer | DBServer | `DBServant` | 同步 RPC | 数据持久化 |
| LobbyServer | SceneServer | `SceneServant` | 同步 RPC | 转发场景请求 |
| SceneServer | LobbyServer | `Scene2LobbyPush` | 异步 RPC | 推送玩家事件 |

## 5. 踩坑记录

### 5.1 TARS Response 复用问题 (已解决 ✅)

**问题描述**：
在 `SceneImp::getScenePlayers` 中，多次调用返回的玩家列表出现重复，如 playerId 1001 出现多次。

**根因**：
TARS 框架的 Response 对象可能被复用，旧数据残留在 buffer 中未清空。

**修复方案**：
```cpp
// SceneImp.cpp 第 97 行
tars::Int32 SceneImp::getScenePlayers(...)
{
    rsp.ret = 0;
    rsp.msg = "success";
    rsp.players.clear();  // ← 必须清空，释放残留数据
    // ...
}
```

**教训**：
- TARS 的输出参数是 **状态ful** 的，需要开发者主动管理生命周期
- 每次返回前，显式清空容器，避免残留数据累积
