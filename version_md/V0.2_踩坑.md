# V0.2 踩坑记录

## 概述

V0.2 在 V0.1 基础上实现了多 Scene 场景管理，支持多玩家同场景协同。在开发过程中遇到了新的典型问题，本文档记录这些问题及解决方案。

---

## 踩坑 1：TARS Response 复用导致数据累积

### 问题描述

在测试 `getScenePlayers` 接口时，发现 test 5b 返回的玩家列表中，同一个 playerId 重复出现多次：

```
Players in scene 1: 4
     Player[0]: id=1001
     Player[1]: id=1001
     Player[2]: id=1002
     Player[3]: id=1003
     Player[4]: id=1004
```

实际期望的是 4 个不同的玩家 (1001, 1002, 1003, 1004)。

### 原因分析

**TARS 框架的 Response 复用机制**：

1. TARS 框架在处理 RPC 响应时，response 对象由框架管理并可能被复用
2. 序列化层为了性能考虑，**不会自动重置 vector/map 等容器**
3. 旧的 `players` 数据残留在 buffer 中

测试流程分析：

```
Test 1: enterScene(1001) → getScenePlayers → players=[]
Test 4: getScenePlayers  → players=[1001]    ← 填充了数据
Test 5: enterScene(1002/1003/1004)          ← 修改全局数据
Test 5b: getScenePlayers → players=[1001, 1001, 1002, 1003, 1004]← 累积了！
```

**关键**：原代码只做了 `push_back`，没有清空操作，每次调用都会追加。

### 问题代码

```cpp
tars::Int32 SceneImp::getScenePlayers(..., GetScenePlayersRsp &rsp, ...)
{
    rsp.ret = 0;
    rsp.msg = "success";
    // ❌ 缺少清空操作！rsp.players 可能残留旧数据

    auto& globalPlayers = g_app.getGlobalPlayers();
    for (const auto &kv : globalPlayers)
    {
        if (kv.second.sceneId == sceneId)
        {
            rsp.players.push_back(info);  // 不断追加...
        }
    }
    return 0;
}
```

### 解决方案

在函数开头**显式清空**输出容器：

```cpp
tars::Int32 SceneImp::getScenePlayers(..., GetScenePlayersRsp &rsp, ...)
{
    rsp.ret = 0;
    rsp.msg = "success";
    rsp.players.clear();  // ✅ 显式清空，释放旧的 buffer

    auto& globalPlayers = g_app.getGlobalPlayers();
    for (const auto &kv : globalPlayers)
    {
        if (kv.second.sceneId == sceneId)
        {
            rsp.players.push_back(info);
        }
    }
    return 0;
}
```

### 修复位置

- 文件：`server/SceneServer/src/SceneImp.cpp`
- 行号：第 97 行

### 验证结果

修复后测试输出正确：

```
Players in scene 1: 4
     Player[0]: id=1001
     Player[1]: id=1002
     Player[2]: id=1003
     Player[3]: id=1004
```

### 注意事项

- **TARS 的 response 参数是状态ful的**，需要开发者主动管理生命周期
- 框架不会自动重置输出参数，这是设计权衡（性能优先）
- 所有输出参数（vector、map、string 等）在使用前都应考虑是否需要清空

## 总结

| 踩坑点 | 根因 | 解决方案 |
|--------|------|----------|
| Response 数据累积 | TARS 框架复用 response buffer，未自动重置 | `rsp.players.clear()` 显式清空 |
