# V0.3 - Scene同步与数据持久化

> **目标**: 实现 SceneServer 玩家数据同步到 DBServer，以及位置数据持久化到 MySQL（暂不使用 TcaplusDB）

## 完成时间
- 预计: 2-3 天

## 功能特性

### 核心功能
1. **数据同步** - SceneServer 定时同步玩家数据到 DBServer
2. **位置持久化** - 玩家位置存储到 MySQL
3. **数据恢复** - 玩家重连后从 DBServer 恢复位置
4. **玩家列表广播** - SceneServer 向 LobbyServer 同步在线玩家信息

### 服务架构
```
┌─────────────────────────────────────────────────────────────────────────┐

└───────────┬─────────────────────────────────────────────────────────────┘
            │
            │ Tars RPC (内部调用)
            │
            ▼
┌─────────────────────┐                           ┌─────────────────────┐

│     (10000)         │                           │   (10002)           │

│  - MySQL 位置存储   │◄─────── Tars RPC ────────│  - 玩家数据内存      │

┌─────────────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────────────┤
│  Client ──▶ LobbyServer ──▶ DBServer       (账号/角色数据)              │
│  Client ──▶ LobbyServer ──▶ SceneServer    (进入场景/移动)               │
│                                                                          │
│  SceneServer ──▶ LobbyServer ──▶ Client   (玩家进入/离开通知)             │
│  SceneServer ──▶ DBServer              (定时同步位置数据)                │
│  LobbyServer ──▶ DBServer              (离线时同步最终数据)              │
└─────────────────────────────────────────────────────────────────────────┘
```

### MySQL 表结构

```sql
-- 位置信息表
CREATE TABLE `t_player_position` (
    `player_id` BIGINT PRIMARY KEY,
    `scene_id` INT NOT NULL DEFAULT 1,
    `pos_x` FLOAT NOT NULL DEFAULT 0,
    `pos_y` FLOAT NOT NULL DEFAULT 0,
    `pos_z` FLOAT NOT NULL DEFAULT 0,
    `level` INT NOT NULL DEFAULT 1,
    `role_name` VARCHAR(64) NOT NULL,
    `last_update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_scene_id (`scene_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 潜在风险

| 风险 | 应对措施 |
|------|----------|
| 同步延迟导致数据丢失 | 断线时强制同步最终数据 |
| 多 SceneServer 场景数据 | 使用 playerId 分片同步 |
| MySQL 写入性能 | 批量异步写入 |
