# V0.3 - 多场景与数据持久化

> **目标**: 实现多场景支持和 TcaplusDB 位置存储

## 完成时间
- 预计: 2-3 天

## 功能特性

### 核心功能
1. **多场景支持** - 支持多个 SceneServer 实例
2. **TcaplusDB** - 玩家位置持久化存储
3. **场景切换** - 玩家可在不同场景间切换

### 服务架构
```
┌─────────────────────────────────────────────────────────────────────────┐
│                                Client                                   │
│                     【单一接入点：只连接 LobbyServer】                    │
│                        Tars 协议 (TCP)                                   │
└────────────────────────────────┬────────────────────────────────────────┘
                                 │
                                 │ 所有请求都通过 LobbyServer 转发
                                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                          LobbyServer                                   │
│                    【统一接入层 / 网关层】                                │
│                                                                            │
│  - 客户端连接管理（心跳/断连/重连）                                       │
│  - playerId ↔ connId 映射管理                                              │
│  - 场景列表/选择                                                          │
│  - 场景切换路由                                                          │
└───────────┬─────────────────────────────────────────────────────────────┘
            │
            │ Tars RPC (内部调用)
            │
            ▼
┌─────────────────────┐                           ┌─────────────────────┐
│     DBServer        │                           │   SceneServer       │
│     (20010)         │                           │   (20002+)          │
│                     │                           │                     │
│  - MySQL 账号/角色   │                           │  - 场景管理          │
│  - TcaplusDB 位置   │◄─────── Tars RPC ────────│  - 移动处理          │
│                     │       (位置持久化)          │  - 位置广播          │
└─────────────────────┘                           └─────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                              通信流程                                    │
├─────────────────────────────────────────────────────────────────────────┤
│  Client ──▶ LobbyServer ──▶ DBServer       (账号/角色数据)              │
│  Client ──▶ LobbyServer ──▶ SceneServer    (进入场景/移动)               │
│                                                                          │
│  SceneServer ──▶ DBServer              (位置持久化到 TcaplusDB)         │
│  SceneServer ──▶ LobbyServer ──▶ Client  (回调推送)                     │
└─────────────────────────────────────────────────────────────────────────┘
```

## 技术方案

### 协议扩展

> **说明**: V0.3 在 V0.2 的基础上扩展协议，只需修改/新增文件：

**目录结构**:
```
server/tars/
├── GameDemoBase.tars    # 不变，已包含 SceneInfo
├── Account.tars         # 不变
├── Scene.tars           # 扩展，新增 getSceneList、requestEnterScene
├── DB.tars              # 扩展，新增 TcaplusDB 操作
└── (生成的 .h/.cpp)
```

```tars
// ========== server/tars/Scene.tars ==========
// V0.3 扩展：新增场景列表、进入场景接口

#include "GameDemoBase.tars"

module GameDemo {

    // 获取场景列表
    struct GetSceneListReq {
        0 require long playerId;
    };
    
    struct GetSceneListRsp {
        0 require int ret;
        1 optional string msg;
        2 optional vector<SceneInfo> scenes;
    };
    
    // 进入场景请求
    struct EnterSceneReq {
        0 require long playerId;
        1 require int sceneId;
    };
    
    struct EnterSceneRsp {
        0 require int ret;
        1 optional string msg;
        2 optional int sceneId;
        3 optional float posX;
        4 optional float posY;
        5 optional float posZ;
        6 optional vector<PlayerInfo> nearbyPlayers;
    };
    
    // 大厅心跳
    struct HeartBeatReq {
        0 require long playerId;
    };
    
    interface SceneServant {
        // 获取场景列表
        int getSceneList(1 require GetSceneListReq req, 2 require GetSceneListRsp rsp);
        
        // 请求进入场景
        int requestEnterScene(1 require EnterSceneReq req, 2 require EnterSceneRsp rsp);
        
        // 心跳
        int heartBeat(1 require HeartBeatReq req);
    };
};
```

```tars
// ========== server/tars/DB.tars ==========
// V0.3 扩展：新增 TcaplusDB 位置存储

#include "GameDemoBase.tars"

module GameDemo {

    // 位置信息 (TcaplusDB)
    struct PlayerPos {
        0 require long playerId;
        1 require int sceneId;
        2 require float x;
        3 require float y;
        4 require float z;
        5 require int64 lastMoveTime;
    };
    
    interface DBPositionServant {
        // 保存玩家位置
        int savePosition(1 require PlayerPos pos);
        
        // 获取玩家位置
        int getPosition(1 require long playerId, 2 out PlayerPos pos);
        
        // 批量获取场景内玩家位置
        int getScenePositions(1 require int sceneId, 2 out vector<PlayerPos> positions);
    };
};
```

### 协议设计说明

> **注意**: V0.3 的协议与 V0.2 有以下变化：
> 1. `SceneInfo` 已在 `GameDemoBase.tars` 中定义，所有服务共用
> 2. `SceneServant` 扩展，新增 `getSceneList` 和 `requestEnterScene` 接口
> 3. `DB.tars` 新增 `DBPositionServant` 用于 TcaplusDB 操作

**接口变化对比**：

| V0.2 接口 | V0.3 接口 | 变化说明 |
|-----------|-----------|----------|
| - | SceneServant::getSceneList | **新增** |
| - | SceneServant::requestEnterScene | **新增** |
| - | DBPositionServant::savePosition | **新增** |
| - | DBPositionServant::getPosition | **新增** |
| - | DBPositionServant::getScenePositions | **新增** |

> **架构说明**：Client 只连接 LobbyServer，由 LobbyServer 调用 SceneServer 进行场景操作，SceneServer 调用 DBServer 进行位置持久化。

### TcaplusDB 表设计

```protobuf
// PlayerPos.tcaplus
table PlayerPos {
    player_id: int64;
    scene_id: int32;
    x: float;
    y: float;
    z: float;
    last_move_time: int64;
    
    primary_key(player_id);
};
```
