# V0.3 - 移动同步增强

> **目标**: 优化移动同步性能，实现 AOI 九宫格算法

## 完成时间
- 预计: 3-4 天

## 现有代码架构

### 玩家存储（V0.2 已实现）

**注意**: V0.3 将玩家数据和 AOI 索引合并到统一的 `PlayerManager` 中管理。

### 整体架构

```
SceneServer (全局单例，Application 级别)
    └── PlayerManager _playerManager  ← 全局唯一，供所有 Imp 实例共享
            ├── _players (玩家数据 map)
            ├── _grids (AOI 九宫格索引)
            └── _rwlock (单一读写锁)

SceneImp (每个请求一个实例)
    └── 缓存 PlayerManager 指针 _playerMgr
```

**为什么 PlayerManager 在 SceneServer 层而不是 SceneImp 层**：
- Tars 框架中 `SceneImp` 是按请求实例化的，多个线程会各自创建独立的 `SceneImp`
- 如果 `_playerManager` 在 `SceneImp` 中，每个线程会有独立的数据，导致数据不共享
- 将 `PlayerManager` 放在 `SceneServer` 层，作为全局单例，所有 Imp 线程共享同一份数据

**为什么要缓存 PlayerManager 指针**：
- 避免每次调用都要通过 `g_app.getPlayerManager()` 获取
- Tars 框架保证 `SceneServer::initialize()` 先于 `SceneImp::initialize()` 执行，所以指针在 Imp 生命周期内始终有效

**接口设计原则**：
- 对外只暴露 `playerEnter()`、`playerMove()`、`playerLeave()` 三个组合接口
- 每个接口一次性完成数据和 AOI 格子更新，减少调用方复杂度
- 内部实现统一使用单一读写锁，保证原子性

### 通知机制（V0.2 已实现）

```cpp
// SceneImp.cpp - 现有实现
vector<long> SceneImp::calcNotifyList(int sceneId, long excludePlayerId)
{
    vector<long> notifyList;
    for (const auto& kv : g_app.getGlobalPlayers())
    {
        if (kv.second.sceneId == sceneId && kv.second.playerId != excludePlayerId)
        {
            notifyList.push_back(kv.second.playerId);
        }
    }
    return notifyList;
}
```

**V0.3 将在此基础上增强 AOI 能力**，使用 `getViewPlayers()` 替代全量遍历。

## 技术方案

### AOI 九宫格算法

```
    ┌──────────┬────────┬─────────┐
    │     1    │   2    │    3    │     场景被划分为网格
    │  M-1,N-1 │  M,N1  │  M+1,N-1│     每个格子为固定大小
    ├──────────┼────────┼─────────┤     玩家视野 = 3x3 或 5x5 九宫格
    │     4    │   5    │    6    │
    │  M-1,N   │  M,N   │  M+1,N  │     玩家进入/离开/移动时
    ├──────────┼────────┼─────────┤     检查视野内格子是否有玩家变化
    │     7    │   8    │    9    │     有变化则通知视野内玩家
    │  M-1,N+1 │  M,N+1 │  M+1,N+1│
    └──────────┴────────┴─────────┘
```

### 配置参数说明

```tars
// 配置文件
AOI_GRID_SIZE = 10.0       // 格子大小(米)，地图被划分成网格
AOI_VIEW_RANGE = 30.0      // 视野范围(米)，同时也是服务端推送范围
MOVE_FREQUENCY_LIMIT = 10  // 每秒最多移动10次
BROADCAST_INTERVAL = 50    // 批量广播间隔(ms)
```

**设计原则**：玩家视野 = 服务端九宫格推送范围，简化实现。

**AOI_GRID_SIZE vs AOI_VIEW_RANGE 的关系**：
- `AOI_GRID_SIZE`：每个格子的大小（如 10×10 米）
- `AOI_VIEW_RANGE`：玩家视野范围，同时也是服务端推送范围（如 30 米）
- 计算：视野范围决定九宫格半径 = `AOI_VIEW_RANGE / AOI_GRID_SIZE` = 3 格（单边）
- 视野内格子数 = 3×3 = 9 个格子

```
    ┌─────┬─────┬─────┐
    │  1  │  2  │  3  │
    ├─────┼─────┼─────┤
    │  4  │ [5] │  6  │    [5] = 当前玩家所在格子
    ├─────┼─────┼─────┤    服务端推送 = 玩家视野 = 3×3 九宫格
    │  7  │  8  │  9  │
    └─────┴─────┴─────┘
```

**服务端与客户端职责**：
```
服务端 (SceneServer)
├── 维护地图格子数据
├── 计算玩家九宫格邻居
├── 推送视野内玩家变化 → 客户端

客户端 (Client)
├── 接收服务端推送
├── 渲染推送列表中的玩家（服务端已过滤，无需二次判断）
└── 本地不做视野计算
```

**格子内移动 vs 跨格子移动**：
- **格子内移动**：位置变化但仍在同一格子内 → **仍需同步**给视野内玩家（只是位置更新）
- **跨格子移动**：离开当前格子 → **重新计算视野玩家**（可能有人进入/离开视野）

## 实现步骤

### Step 1: PlayerManager 模块设计

**设计原则**：
1. `PlayerManager` 统一管理玩家数据和 AOI 索引
2. 单一读写锁保护所有数据（读并行，写独占）
3. 对外只暴露组合接口，隐藏内部实现细节

```cpp
// PlayerManager.h
// 统一管理玩家数据和 AOI 九宫格索引
class PlayerManager {
public:
    // 对外接口（组合操作，一次性完成数据+AOI更新）
    void playerEnter(Int64 playerId, float x, float y, float z, Int32 sceneId, Int32 level);
    void playerMove(Int64 playerId, float x, float y, float z);
    void playerLeave(Int64 playerId);

    // 查询接口
    vector<Int64> getViewPlayers(Int64 playerId);
    GlobalPlayerData* getPlayer(Int64 playerId);

    // 初始化/清理
    void init(int sceneWidth, int sceneHeight, float gridSize);
    void clear();

private:
    // 辅助函数
    pair<int, int> posToGrid(float x, float y) const;
    int gridToId(int gx, int gy) const;
    vector<int> getNeighborGrids(int gx, int gy) const;
    int calcGridId(float x, float y) const;

private:
    float _gridSize;
    int _sceneWidth;
    int _sceneHeight;
    int _gridXCount;
    int _gridYCount;

    unordered_map<Int64, GlobalPlayerData> _players;              // 玩家数据
    unordered_map<int, unordered_set<Int64>> _grids;              // 格子 -> 玩家ID列表
    pthread_rwlock_t _rwlock;                                      // 统一读写锁
};
```

**设计说明**：

| 数据结构 | 存储内容 | 用途 |
|----------|----------|------|
| `_players` | 玩家完整数据 (位置、等级等) | 唯一数据源 |
| `_grids` | 格子 -> playerId 列表 | 快速查询视野内玩家 |

**对外接口说明**：

| 接口 | 内部操作 | 说明 |
|------|----------|------|
| `playerEnter()` | 添加数据 + 加入格子 | 玩家进入场景 |
| `playerMove()` | 更新数据 + 更新格子 | 玩家移动 |
| `playerLeave()` | 离开格子 + 移除数据 | 玩家离开场景 |

**getViewPlayers() 工作流程**：
1. 从 `_players` 获取当前玩家坐标
2. 计算当前玩家所在格子
3. 从 `_grids` 取出周围9格的所有玩家ID
4. 排除自己，返回视野内玩家列表

**为什么不存储玩家所在格子**：
- 可以用 `calcGridId(x, y)` 直接计算 O(1)，不存储
- 移动时获取旧格子：用 `calcGridId(旧x, 旧y)` 计算即可
- 避免数据不一致：如果坐标更新了但格子缓存没同步会出错

### Step 2: SceneServer 改造

**设计原则**：
- `PlayerManager` 作为 `SceneServer` 的成员变量，确保全局唯一
- `SceneImp` 缓存 `PlayerManager` 指针访问共享数据

```cpp
// SceneServer.h
class SceneServer : public Application {
public:
    ~SceneServer() {};

    // 获取玩家管理器（全局单例，供所有 SceneImp 共享）
    PlayerManager& getPlayerManager() { return _playerManager; }

public:
    virtual void initialize();
    virtual void destroyApp();

private:
    PlayerManager _playerManager;  // 全局唯一的玩家管理器
};
```

```cpp
// SceneServer.cpp
void SceneServer::initialize() {
    // 初始化玩家管理器（在 SceneServer 层初始化，确保全局唯一）
    _playerManager.init(1000, 1000, 10.0f);  // 场景 1000x1000，格子 10x10

    // 注册 SceneServant 接口
    addServant<SceneImp>(...);
}

void SceneServer::destroyApp() {
    _playerManager.clear();
}
```

```cpp
// SceneImp.cpp - enterScene 改造示例
tars::Int32 SceneImp::enterScene(const EnterSceneReq &req, EnterSceneRsp &rsp, ...) {
    // 通过 PlayerManager 添加玩家（一次性完成数据和 AOI 格子添加）
    _playerMgr->playerEnter(req.playerId, 0.0f, 0.0f, 0.0f, req.sceneId, 1);

    // 获取视野内玩家
    vector<Int64> viewPlayers = _playerMgr->getViewPlayers(req.playerId);

    // 填充视野内其他玩家信息
    for (Int64 pid : viewPlayers) {
        auto* p = _playerMgr->getPlayer(pid);
        if (p) {
            PlayerInfo info;
            info.playerId = p->playerId;
            info.sceneId = p->sceneId;
            info.level = p->level;
            info.x = p->x;
            info.y = p->y;
            info.z = p->z;
            rsp.players.push_back(info);
        }
    }

    // 异步通知 LobbyServer
    notifyPlayerEnter(req.playerId, req.sceneId, rsp.self, viewPlayers);
    return 0;
}
```

```cpp
// SceneImp.cpp - move 改造示例
tars::Int32 SceneImp::move(const MoveReq &req, MoveRsp &rsp, ...) {
    // 更新玩家位置（一次性完成数据和 AOI 格子更新）
    _playerMgr->playerMove(req.playerId, req.x, req.y, req.z);

    // 获取视野内玩家
    vector<Int64> viewPlayers = _playerMgr->getViewPlayers(req.playerId);

    // 异步通知 LobbyServer
    auto* player = _playerMgr->getPlayer(req.playerId);
    if (player) {
        notifyPlayerMove(req.playerId, player->sceneId, req.x, req.y, req.z, viewPlayers);
    }
    return 0;
}
```

```cpp
// SceneImp.cpp - leaveScene 改造示例
tars::Int32 SceneImp::leaveScene(const LeaveSceneReq &req, LeaveSceneRsp &rsp, ...) {
    // 获取玩家信息用于通知
    auto* player = _playerMgr->getPlayer(req.playerId);
    Int32 sceneId = req.sceneId;
    if (player) {
        sceneId = player->sceneId;
    }

    // 获取离开前需要通知的玩家（此时玩家还在 AOI 中）
    vector<Int64> notifyList = _playerMgr->getViewPlayers(req.playerId);

    // 从玩家管理器移除（一次性完成 AOI 格子移除和数据移除）
    _playerMgr->playerLeave(req.playerId);

    // 异步通知 LobbyServer
    notifyPlayerLeave(req.playerId, sceneId, notifyList);
    return 0;
}
```
