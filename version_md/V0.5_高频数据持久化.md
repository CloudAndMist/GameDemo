# V0.5 - 高频数据持久化

> **目标**: 实现高频位置数据的异步持久化，不阻塞 SceneServer 游戏业务逻辑
>
> **策略**: SceneServer 直接调用 KVServant 异步接口，DBServer 同步写入 TcaplusDB

## 核心原则

1. **不阻塞游戏逻辑**: 位置更新走异步 RPC，SceneServer 毫秒级返回
2. **简单可靠**: 去掉 MQ 层，直接 RPC 调用
3. **场景分离**: 断线同步保存，重连同步读取，正常移动异步保存

## 架构设计

### 通信架构

```
┌──────────────────────────────────────────────────────────────┐
│                          SceneServer                          │
│  • 内存存储 (实时热数据)                                        │
│  • 玩家位置、状态                                              │
│  • 只依赖 KVServant 接口                                       │
└──────────────────────────────────────────────────────────────┘
                                 │
              ┌──────────────────┴──────────────────┐
              │                                     │
         异步调用 (async_xxx)                   同步调用 (xxx)
         位置更新等高频操作                    断线保存/重连读取
              │                                     │
              ▼                                     ▼
┌──────────────────────────────────────────────────────────────┐
│                           DBServer                            │
│  • KVServant (RPC 服务端)                                     │
│  • 直接写入 TcaplusDB                                         │
└──────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
                         ┌─────────────┐
                         │  TcaplusDB  │
                         └─────────────┘
```

### 数据分层

| 数据类型 | 存储位置 | 写入频率 | 示例 |
|----------|----------|----------|------|
| 低频持久化 | MySQL | 低 | 账号、角色、背包 |
| 高频缓存 | SceneServer 内存 | 极高 | 当前位置、在线状态 |
| 高频持久化 | TcaplusDB | 中高 | 位置快照、断线恢复 |

## KVServant 接口设计

### 接口定义

```tars
// ========== KV.tars ==========
module GameDemo
{
    // 高频数据错误码
    const int ERR_KV_NOT_FOUND = 6001;
    const int ERR_KV_TCAPLUS_ERROR = 6002;

    // 高频玩家数据 (位置快照)
    struct PlayerKVData
    {
        0 require long playerId;       // 玩家ID (主键 Key)
        1 require int level;           // 等级
        2 require float x;             // 位置X
        3 require float y;             // 位置Y
        4 require float z;             // 位置Z
        5 require int sceneId;         // 场景
        6 optional long updateTime;    // 最后更新时间 (Unix时间戳，仅作记录)
    };

    interface KVServant
    {
        // 保存单个玩家数据
        // 框架自动生成 async_savePlayerData() 异步版本
        int savePlayerData(PlayerKVData data);
        
        // 批量保存玩家数据 (用于全量快照)
        int batchSavePlayerData(vector<PlayerKVData> dataList);
        
        // 获取玩家数据
        int getPlayerData(long playerId, out PlayerKVData data);

        // 删除玩家数据
        int deletePlayerData(long playerId);

        // 批量获取玩家数据
        int batchGetPlayerData(vector<long> playerIds, out vector<PlayerKVData> dataList);
    };
};
```

### Tars 异步调用说明

Tars 框架自动为每个同步接口生成异步版本：

```cpp
// 同步调用 - 阻塞等待，适合断线保存、重连读取
kvPrx->savePlayerData(data);

// 异步调用 - callback 为空时表示"发完即忘"，不阻塞游戏逻辑
kvPrx->async_savePlayerData(NULL, data);
```

## 持久化策略

### 调用场景

| 场景 | 调用方式 | 说明 |
|------|----------|------|
| **enterScene** | `getPlayerData()` + `savePlayerData()` | 从 DB 恢复/初始化玩家数据 |
| **leaveScene** | `savePlayerData()` | **必须同步落盘**，防止数据丢失 |
| **断线** | `savePlayerData()` | **必须同步落盘**，兜底保证 |
| 位置移动 | `async_savePlayerData()` | 高频异步，不阻塞 |
| 重连读取 | `getPlayerData()` | 必须同步获取 |

> **为什么 leaveScene 必须同步保存？**
> 
> leaveScene 会清除内存中的玩家数据。如果用异步保存，请求可能还在传输中，此时 SceneServer 崩溃就会丢数据。必须等同步保存落盘成功后再清除内存。

### 全量快照 (兜底机制)

作为异步保存的兜底，定时全量快照保证数据不丢失：

```
定时器触发 (每30秒)
     │
     ▼
遍历 _players map
     │
     ▼
分批收集 (每批100条)
     │
     ▼
批量写入 DBServer
     │
     ▼
继续下一批...
```

**为什么需要全量快照？**
- 异步保存是"发完即忘"，不保证到达
- 即使异步保存失败，定期全量快照也能恢复数据
- 与 leaveScene/断线保存 形成双重保险

### enterScene 流程

每次玩家进入场景时，先检查内存，再决定是否需要从 DB 恢复：

```
玩家 enterScene
     │
     ▼
┌─────────────────────────┐
│  内存中是否有该玩家 ?     │
└─────────────────────────┘
     │
     ├── Yes ──→ 直接复用内存数据(PlayerData和AOI)
     │            标记在线
     │            (快速路径，避免不必要的 DB 调用)
     │
     └── No ──→ 从 DB 恢复/初始化
                     │
                     ▼
              ┌─────────────────────────┐
              │  DB 有数据 ? │ sceneId ? │
              └─────────────────────────┘
                     │
                     ├─ 没数据 ──→ 新玩家，在本 scene 初始化
                     │                    └──▶ 同步保存
                     │
                     ├─ 有数据 + sceneId 不同 ──→ 在本 scene 初始化
                     │                               └──▶ 同步保存
                     │
                     └─ 有数据 + sceneId 相同 ──→ 原地恢复
                                                      不需要同步保存
```

**三种客户端场景**：

| 场景 | 内存状态 | 处理方式 |
|------|----------|----------|
| 正常进入 | 无 | 从 DB 初始化 |
| 快速重连（服务器未重启） | 有 | 直接复用内存 |
| 重启后重连 | 无 | 从 DB 恢复 |

**LobbyServer 逻辑不变** - 客户端和 LobbyServer 保持连接，SceneServer 重启对 LobbyServer 透明。

### 异步调用逻辑

```
玩家位置变化
     │
     ▼
SceneServer 调用 async_savePlayerData()
     │
     ├──▶ Tars RPC 发送请求 (毫秒级)
     │
     ├──▶ 函数立即返回
     │
     ▼
继续处理游戏逻辑 (不等待 DBServer)
```

```
DBServer 端 (独立处理):
     │
     ▼
接收 RPC 请求
     │
     ▼
同步写入 TcaplusDB
     │
     ▼
返回响应 (SceneServer 不关心结果)
```

### PlayerManager 集成

```cpp
// ========== PlayerManager.h ==========

class PlayerManager
{
private:
    KVPrx _kvPrx;  // KVServant 代理

public:
    // ========== 数据恢复 ==========
    
    /**
     * 进入场景时恢复玩家数据
     * 先检查内存，有则直接复用；无则从 DB 恢复/初始化
     */
    void restoreOnEnter(int64_t playerId, int32_t targetSceneId);
    
    // ========== 位置变化 ==========
    
    // 玩家位置变化 → 异步，不阻塞
    void onPositionChange(int64_t playerId, float x, float y, float z);
    
    // ========== 断线/离开处理 ==========
    
    // 玩家离开场景 → 同步保存后清除内存
    void onPlayerLeave(int64_t playerId);
    
    // 玩家断线 → 同步，防御性落盘
    void onPlayerOffline(int64_t playerId);
    
    // ========== 全量快照 ==========
    
    // 后台线程定时全量快照 (兜底机制)
    void startPeriodicSnapshot(int intervalSeconds = 30);
    void stopPeriodicSnapshot();
    void snapshotAllPlayers();  // 触发一次全量快照

private:
    Timer* _snapshotTimer;  // 定时快照计时器
};
```

```cpp
// ========== PlayerManager.cpp ==========

// ========== 核心：进入场景时恢复数据 ==========

void PlayerManager::restoreOnEnter(int64_t playerId, int32_t targetSceneId)
{
    // 1. 先检查内存 (快速路径)
    auto* existing = getPlayer(playerId);
    if (existing != nullptr)
    {
        // 内存已有，直接复用
        TLOG_INFO("PlayerManager: hit memory cache, playerId=" << playerId << endl);
        setOnline(playerId, true);
        return;
    }
    
    // 2. 内存没有，从 DB 恢复
    PlayerKVData dbData;
    int ret = _kvPrx->getPlayerData(playerId, dbData);
    
    // 3. 根据数据情况决策
    if (ret != 0)
    {
        // 情况A: 没数据 → 新玩家
        TLOG_INFO("PlayerManager: new player, playerId=" << playerId << endl);
        
        // 在本 scene 初始化位置 (随机出生点)
        float x = randomSpawnX();
        float y = 0.0f;
        float z = randomSpawnZ();
        
        // 添加到内存
        playerEnter(playerId, x, y, z, targetSceneId, 1);
        
        // 同步保存到 DB
        savePlayerDataSync(playerId);
    }
    else if (dbData.sceneId != targetSceneId)
    {
        // 情况B: 有数据但 sceneId 不同 → 跨场景
        TLOG_INFO("PlayerManager: player from other scene, playerId=" << playerId 
                  << ", from=" << dbData.sceneId << ", to=" << targetSceneId << endl);
        
        // 在本 scene 初始化位置
        float x = randomSpawnX();
        float y = 0.0f;
        float z = randomSpawnZ();
        
        // 添加到内存
        playerEnter(playerId, x, y, z, targetSceneId, dbData.level);
        
        // 同步保存到 DB
        savePlayerDataSync(playerId);
    }
    else
    {
        // 情况C: 有数据且 sceneId 相同 → 原地恢复
        TLOG_INFO("PlayerManager: restore player from DB, playerId=" << playerId 
                  << ", x=" << dbData.x << ", y=" << dbData.y << ", z=" << dbData.z << endl);
        
        // 恢复到内存
        playerEnter(playerId, dbData.x, dbData.y, dbData.z, dbData.sceneId, dbData.level);
        
        // 不需要同步保存，位置没变
    }
}

// 同步保存玩家数据到 DB
void PlayerManager::savePlayerDataSync(int64_t playerId)
{
    auto* player = getPlayer(playerId);
    if (!player) return;
    
    PlayerKVData data;
    data.playerId = playerId;
    data.x = player->x;
    data.y = player->y;
    data.z = player->z;
    data.sceneId = player->sceneId;
    data.level = player->level;
    data.updateTime = time(NULL);  // 记录更新时间
    
    // 同步调用，等待落盘
    _kvPrx->savePlayerData(data);
}

// ========== 位置变化 → 异步，不阻塞 ==========

void PlayerManager::onPositionChange(int64_t playerId, float x, float y, float z)
{
    auto* player = getPlayer(playerId);
    if (!player) return;
    
    // 更新内存
    player->x = x;
    player->y = y;
    player->z = z;
    
    // 构造数据
    PlayerKVData data;
    data.playerId = playerId;
    data.x = x;
    data.y = y;
    data.z = z;
    data.sceneId = player->sceneId;
    data.level = player->level;
    data.updateTime = time(NULL);  // 记录更新时间
    
    // 异步调用，不关心返回，不阻塞
    _kvPrx->async_savePlayerData(NULL, data);
}

// ========== 离开场景 → 同步，必须落盘 ==========

void PlayerManager::onPlayerLeave(int64_t playerId)
{
    // 必须先同步保存，确保落盘后再清除内存
    savePlayerDataSync(playerId);
    
    // 清除内存 (此时数据已安全)
    playerLeave(playerId);
}

// ========== 断线 → 同步，防御性落盘 ==========
// 
// 玩家掉线后，可能：
// 1. 快速重连 (此时内存数据还在)
// 2. 等待一段时间后重连 (内存可能被清理)
// 3. 不再重连，LobbyServer 发送 leaveScene
//
// 为了防止情况 2/3 造成数据丢失，在玩家掉线时就先落盘一次。
// 即使后续 LobbyServer 发送 leaveScene，也会再同步保存一次（不会重复）。
// 这样保证了数据不会因为异步保存失败而丢失。

void PlayerManager::onPlayerOffline(int64_t playerId)
{
    // 同步保存
    savePlayerDataSync(playerId);
    
    // 清除内存
    playerLeave(playerId);
}

// ========== 全量快照 (兜底机制) ==========

void PlayerManager::startPeriodicSnapshot(int intervalSeconds)
{
    _snapshotTimer = new Timer(intervalSeconds * 1000, [this]() {
        snapshotAllPlayers();
    });
    _snapshotTimer->start();
}

void PlayerManager::stopPeriodicSnapshot()
{
    if (_snapshotTimer)
    {
        _snapshotTimer->stop();
        delete _snapshotTimer;
        _snapshotTimer = nullptr;
    }
}

void PlayerManager::snapshotAllPlayers()
{
    TLOG_DEBUG("PlayerManager: starting periodic snapshot..." << endl);
    
    // 读取全局锁
    pthread_rwlock_rdlock(&_rwlock);
    
    // 收集所有在线玩家数据
    vector<PlayerKVData> allData;
    allData.reserve(_players.size());
    
    for (const auto& pair : _players)
    {
        const auto& player = pair.second;
        if (player.isOnline)  // 只快照在线玩家
        {
            PlayerKVData data;
            data.playerId = player.playerId;
            data.level = player.level;
            data.x = player.x;
            data.y = player.y;
            data.z = player.z;
            data.sceneId = player.sceneId;
            data.updateTime = time(NULL);  // 记录更新时间
            allData.push_back(data);
        }
    }
    
    pthread_rwlock_unlock(&_rwlock);
    
    if (allData.empty())
    {
        TLOG_DEBUG("PlayerManager: no online players to snapshot" << endl);
        return;
    }
    
    // 分批批量写入
    const size_t BATCH_SIZE = 100;
    for (size_t i = 0; i < allData.size(); i += BATCH_SIZE)
    {
        vector<PlayerKVData> batch;
        for (size_t j = i; j < min(i + BATCH_SIZE, allData.size()); ++j)
        {
            batch.push_back(allData[j]);
        }
        
        // 批量写入 DBServer
        _kvPrx->batchSavePlayerData(batch);
    }
    
    TLOG_INFO("PlayerManager: snapshot completed, " << allData.size() << " players saved" << endl);
}
```

### SceneImp 调用示例

```cpp
// ========== SceneImp.cpp ==========

tars::Int32 SceneImp::enterScene(const EnterSceneReq &req, EnterSceneRsp &rsp, ...)
{
    // 1. 从 DB 恢复/初始化玩家数据 (先检查内存，有则直接复用)
    _playerMgr->restoreOnEnter(req.playerId, req.sceneId);
    
    // 2. 获取玩家数据
    auto* player = _playerMgr->getPlayer(req.playerId);
    
    rsp.self.playerId = player->playerId;
    rsp.self.sceneId = player->sceneId;
    rsp.self.x = player->x;
    rsp.self.y = player->y;
    rsp.self.z = player->z;
    rsp.self.level = player->level;
    
    // 3. 获取视野内玩家
    vector<tars::Int64> viewPlayers = _playerMgr->getViewPlayers(req.playerId);
    
    // 4. 填充视野内玩家信息...
    
    // 5. 通知 LobbyServer (LobbyServer 逻辑不变)
    notifyPlayerEnter(req.playerId, req.sceneId, rsp.self, viewPlayers);
    
    return 0;
}

tars::Int32 SceneImp::move(const MoveReq &req, MoveRsp &rsp, ...)
{
    // 更新位置，异步保存
    _playerMgr->playerMove(req.playerId, req.x, req.y, req.z);
    _playerMgr->onPositionChange(req.playerId, req.x, req.y, req.z);
    
    // 通知周围玩家 (异步，不阻塞)
    auto* player = _playerMgr->getPlayer(req.playerId);
    vector<tars::Int64> viewPlayers = _playerMgr->getViewPlayers(req.playerId);
    notifyPlayerMove(req.playerId, player->sceneId, req.x, req.y, req.z, viewPlayers);
    
    return 0;
}
```

## 调用时序图

### 位置更新 (异步，不阻塞)

```
玩家 ──▶ SceneServer.move()
              │
              ▼
        异步 RPC 调用
        async_savePlayerData()
              │
              ▼ (毫秒级返回)
        继续处理移动逻辑
              │
              │ 异步传输
              ▼
        DBServer.KVImp
              │
              ▼
        同步写入 TcaplusDB
```

### 断线保存 (同步，必须落盘)

```
检测到断线 ──▶ SceneServer
                    │
                    ▼
              同步 RPC 调用
              savePlayerData()
                    │
                    ▼ (等待落盘)
              DBServer.KVImp
                    │
                    ▼
              同步写入 TcaplusDB
                    │
                    ▼ (返回成功)
              清理 SceneServer 内存
```

### leaveScene 保存 (同步，必须落盘)

```
玩家 leaveScene ──▶ SceneServer
                        │
                        ▼
                  同步 RPC 调用
                  savePlayerData()
                        │
                        ▼ (等待落盘)
                  DBServer.KVImp
                        │
                        ▼
                  同步写入 TcaplusDB
                        │
                        ▼ (返回成功)
                  清除 SceneServer 内存
```

> **关键**：必须等同步保存成功后再清除内存，防止异步请求未送达导致数据丢失。
